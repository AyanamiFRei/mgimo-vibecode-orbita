# Орбита

Рабочий конкурсный прототип цифрового деканата **вымышленного Университета новых горизонтов**. Неофициальный сервис; все студенты, преподаватели, оценки и документы придуманы. Связи с настоящими системами вузов нет.

**Опубликованное приложение:** [mgimo-vibecode-orbita.vercel.app](https://mgimo-vibecode-orbita.vercel.app). Vercel Hobby + постоянная удалённая БД Turso Free. Состояние публикации и ограничения сетевой проверки описаны в [инструкции](docs/deployment.md).

## Запуск

Нужны Node.js 22+ и npm. После скачивания исходников:

```powershell
npm ci
Copy-Item .env.example .env.local
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Вставьте полученную случайную строку в `NEXTAUTH_SECRET` файла `.env.local`. Значения `NEXTAUTH_URL=http://localhost:3000` и `DATABASE_URL=file:./data/orbita.db` подходят для локальной работы.

```powershell
npm run db:setup
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). Для production-сборки: `npm run build`, затем `npm start`. Команда `start` запускает standalone-сервер, переносит настройки окружения и сохраняет путь к локальной БД независимо от рабочей директории.

## Возможности

- Вход, защищённый профиль, выход и сессия до 8 часов.
- Регистрация собственного аккаунта без почты: выбор вымышленного персонажа и направления. Профиль и учебные данные создаются отдельно; чужие заявки не копируются.
- Расписание двух семестров 2026/27: праздники РФ, официальные переносы, каникулы и сессия. Недельная загрузка и переход к дате.
- Каталог вымышленных преподавателей, часы консультаций, личные обращения и ответы сотрудника внутри прототипа. Внешние письма не отправляются.
- Отдельный раздел «Чаты»: существующие диалоги расположены сверху, выбор преподавателя для нового чата — ниже. Старые ссылки на переписки сохраняют совместимость. Поле сообщения растёт автоматически и уменьшается после отправки.
- Светлая и тёмная тема на входе, регистрации и во всех разделах. Первый визит использует системные настройки, явный выбор сохраняется в cookie и применяется сервером до отображения страницы.
- Оценки, зачёты, прогресс, экзамены, средний балл закрытых дисциплин.
- 4 типа заявок, локальный черновик формы, сохранение в БД, история статусов.
- Очередь сотрудника: принятие в работу, готовность, отказ с пояснением.
- Готовый HTML-образец справки с водяным знаком; печать и сохранение PDF средствами браузера.
- Персональные уведомления, фильтры, сохранение прочитанности, поиск по кабинету.
- Вход от 320 px и кабинет от 360 px; заголовок проверен в WebKit с профилем iPhone SE, управление клавиатурой, модальный фокус, reduced motion.

## Стек и устройство

Next.js App Router, React, TypeScript, NextAuth Credentials/JWT, bcryptjs, libSQL/SQLite, Zod, Lucide. Точные версии закреплены в `package.json` и `package-lock.json`. Внешние шрифты, рекламные трекеры и AI API приложению не нужны.

На локальном сервере/VPS данные хранятся в SQLite. На Vercel используется **внешняя постоянная libSQL БД**; приложение намеренно не разрешает файловую SQLite на Vercel. Подробнее: [архитектура](docs/architecture.md), [безопасность](docs/security.md), [публикация](docs/deployment.md).

`npm run db:setup` создаёт таблицы и вымышленные данные. Повторный запуск сохраняет заявки, статусы, прочитанность, учётные записи и диалоги. Управляемые учебные записи обновляются по календарю двух семестров: 01.09.2026–31.01.2027 и 01.02.2027–30.06.2027. Преподаватели, занятия и границы сессии придуманы; праздники и переносы сверены по правовым актам. Подробнее: [учебный календарь и источники](docs/calendar.md).

## Проверка

```powershell
npm run lint
npm run test:coverage
npm run build
npm run typecheck
npx playwright install chromium webkit
npm run test:e2e
npm audit --omit=dev
```

E2E использует production-сборку на порту 3100 и отдельную новую SQLite БД при каждом прогоне; рабочие заявки не меняются. Скриншоты записываются в `docs/screenshots`. Покрытие относится к серверному коду `lib` и API, интерфейс проверяется E2E. Шаблон CI: [tooling/github-actions/checks.yml](tooling/github-actions/checks.yml). Текущий GitHub OAuth-токен не имеет права workflow, поэтому активный workflow не опубликован. Для включения владелец может скопировать шаблон в `.github/workflows/checks.yml` через GitHub с нужными правами.
